# 数字图像、像素、通道与坐标（Digital Images, Pixels, Channels, and Coordinates）

本页把已经会操作的 NumPy 数组赋予最小图像语义。它不讲滤波、颜色空间转换或相机成像模型。

## 1. 这是什么

**数字图像（digital image）**是在离散空间位置上记录数值的数组。每个位置叫 **像素（pixel）**；每个像素可以只有一个强度值，也可以有多个 **通道（channel）** 分量。

- 灰度图（grayscale image）常用 shape `H×W`；
- RGB 彩色图常用 shape `H×W×3`；
- `H` 是 height（行数），`W` 是 width（列数）。

“常用”不是自动保证。拿到数组时仍需从数据来源确认 axis 与颜色约定。

## 2. 为什么机器视觉需要它

### 为什么现在学

`python.numpy-arrays` 教你操作 shape 和 axis；本页进一步回答这些轴在图像中是什么意思。只有建立这个数据契约，后续显示、ROI、读取、阈值、测量和几何操作才有明确对象。

### 在机器视觉中会在哪里使用

- 判断数组究竟是灰度图、彩色图还是一批数据；
- 用正确的 row/column 访问指定像素和 ROI；
- 解释强度（intensity）的 dtype 与数值范围；
- 识别通道轴并为后续颜色读取/转换建立边界；
- 在图像测量和几何处理中连接像素坐标与数组位置。

## 3. 前置知识

硬前置是 `python.numpy-arrays`：应能读懂二维/三维 shape、axis、indexing 和切片。`math.coordinate-frames` 是 recommended；即使尚未学习，本页也会给出 row/column 与 x/y 的最小约定。

`python.numpy-dtypes` 与本页可以并行：它深入类型运算安全，本页只复用 dtype/range 作为图像表示的一部分，不要求先完成它。

## 4. 核心概念

### pixel 与 channel

灰度图中，一个空间位置通常对应一个数。RGB 图像中，一个空间位置通常对应三个分量：red、green、blue。

```python
gray_value = gray[row, column]
rgb_pixel = rgb[row, column, :]  # shape (3,)
```

通道不是三张互不相关的图，而是同一空间网格上每个像素的多个分量。当前只学习 grayscale 与 RGB；不提前讨论 BGR 文件读取、alpha、颜色管理或其他颜色空间。

### height、width、shape

对常见 `H×W×C` 约定：

| axis | 语义 | 索引范围 |
| --- | --- | --- |
| 0 | height / row | `0 ... H-1` |
| 1 | width / column | `0 ... W-1` |
| 2 | channel | `0 ... C-1` |

因此 `shape=(480,640,3)` 常表示高 480、宽 640、3 通道，而不是宽 480、高 640。

### row/column 与 x/y

NumPy 访问图像使用 `image[row, column]`。在常见像素坐标写法中，横向位置记为 `x=column`，纵向位置记为 `y=row`；原点通常取左上角，x 向右增大，y 向下增大。

所以坐标 `(x=2, y=1)` 对应数组索引 `image[1, 2]`。先声明坐标约定，再做转换；不要把 `(x,y)` 机械地写成 `image[x,y]`。

### intensity、dtype 与 numeric range

**强度（intensity）**是像素数值表达的亮暗或通道量。它的含义必须由 dtype、实际范围和数据约定共同决定：

- 常见 `uint8` 灰度图使用 0–255；
- 浮点图常使用 0–1，但也可能保留 0–255；
- 相同视觉内容可以有不同的数值表示。

```python
gray_float = gray.astype(np.float32) / 255.0
```

该转换改变表示尺度，不应改变相对亮暗或像素位置。转回时必须按 `clip → ×255 → round/rint → astype(np.uint8)` 的顺序处理；`astype(np.uint8)` 本身不会替你完成合理 clipping 或 rounding。

## 5. 初学者直觉解释

把数字图像想成铺在方格纸上的测量表。row 告诉你往下走几格，column 告诉你往右走几格；channel 则是同一格里并排记录的多个量。数组只提供格子和数字，图像数据契约才说明每个数字代表什么。

## 6. 必须掌握到什么程度

- 能解释 grayscale 与 RGB 的最小数组表示。
- 能从 shape 写出 height、width、channel，并访问指定像素。
- 能明确声明左上原点、x/y 方向及其与 row/column 的映射。
- 能联合 dtype、实际 min/max 和约定解释 intensity。
- 能验证 uint8 与 0–1 float 表示转换保持位置和相对强度。

当前不学习 BGR/RGB I/O 差异、alpha、颜色科学、相机模型、采样理论、滤波、压缩或完整数字图像处理。

## 7. 常见误区

- 把 `shape[0]` 当 width、`shape[1]` 当 height。
- 将 `(x,y)` 直接写成 `image[x,y]`。
- 看到三维数组就断定第三轴一定是 RGB。
- 看到 `float32` 就断定数值范围一定是 0–1。
- 把显示出来的颜色当作数组通道和数值约定已经正确的证明。

## 8. Worked Example：从数组读懂图像

```python
import numpy as np

gray = np.array([
    [0, 64, 128, 255],
    [10, 80, 160, 240],
    [20, 100, 180, 220],
], dtype=np.uint8)

assert gray.shape == (3, 4)  # H=3, W=4

# 常见像素坐标 (x=2, y=1) 对应 [row=1, column=2]。
x, y = 2, 1
assert gray[y, x] == 160

# 三个输入 channel 都是 H×W；输出最后增加长度为 3 的 channel axis。
height, width = gray.shape
red = gray
green = np.zeros((height, width), dtype=np.uint8)
blue = 255 - gray
assert red.shape == green.shape == blue.shape == (height, width)

rgb = np.zeros((height, width, 3), dtype=np.uint8)
rgb[:, :, 0] = red    # RGB index 0: red
rgb[:, :, 1] = green  # RGB index 1: green
rgb[:, :, 2] = blue   # RGB index 2: blue
assert rgb.shape == (3, 4, 3)
assert np.array_equal(rgb[y, x], [160, 0, 95])

# uint8 0–255 → float32 0–1。
gray_float = gray.astype(np.float32) / 255.0
assert gray_float.shape == gray.shape
assert gray_float.dtype == np.float32
assert np.isclose(gray_float[y, x], 160 / 255.0)
assert 0.0 <= gray_float.min() <= gray_float.max() <= 1.0

# float32 0–1 → uint8 0–255：先 clip 和舍入，最后才转换 dtype。
gray_restored = np.rint(np.clip(gray_float, 0.0, 1.0) * 255.0).astype(
    np.uint8
)

# 先扩大到安全的有符号 dtype，再计算误差，避免 uint8 减法回绕。
roundtrip_error = np.abs(
    gray_restored.astype(np.int16) - gray.astype(np.int16)
)
max_roundtrip_error = int(roundtrip_error.max())
print("uint8 round-trip max error:", max_roundtrip_error)
assert max_roundtrip_error == 0

# 任意 0–1 float 一旦量化为 uint8，再恢复为 float，通常不会逐元素完全相同。
float_source = np.array([0.0, 0.5, 0.501, 1.0], dtype=np.float32)
encoded = np.rint(np.clip(float_source, 0.0, 1.0) * 255.0).astype(np.uint8)
decoded = encoded.astype(np.float32) / 255.0
float_error = np.abs(decoded - float_source)
print("float quantization max error:", float(float_error.max()))
assert float(float_error.max()) <= 0.5 / 255.0 + 1e-7
```

这个例子分别验证了空间 shape、坐标映射、通道组合和强度尺度。`red`、`green`、`blue` 各自都是 `H×W`；创建 `H×W×3` 输出后，三个赋值把它们放到最后一个 channel axis 的索引 0、1、2，因此每个空间位置最终有三个 RGB 分量。

从原始 `uint8` 出发且中途不修改时，这个 round-trip 可以精确恢复；但任意 0–1 float 被编码为 256 个 `uint8` 等级时会发生量化，恢复后的 float 不保证逐元素完全相同，所以应报告误差而不是只看 dtype。误差计算先转为 `int16` 或直接使用 float，不能让检查本身在 `uint8` 中回绕。

`rgb` 只是为了解释 `H×W×C` 构造的合成 RGB 数据，不代表 OpenCV 文件读取默认采用相同通道顺序。

## 10. Practice 练习

### 理解检查

对 shape `(6,9,3)` 写出每个 axis 的最可能图像语义，并列出仍需向数据来源确认的一项约定。完成标准：正确给出 H=6、W=9、C=3，且不把 RGB 当作仅由 shape 保证。

### 数值练习

在 `5×7` 数组中，将常见像素坐标 `(x=5,y=3)` 转成 NumPy 索引并读取数值。完成标准：索引写为 `[3,5]`；同时画出或文字说明原点、x/y 正方向。

### 视觉小练习

构造一个 `3×4` 灰度图和对应三通道数组，输出 shape、dtype、min/max 和两个指定像素。完成标准：所有 axis 有语义标签；坐标与数组索引一致；用断言核对通道值。

### 表示转换

沿用 Worked Example，将 `uint8` 灰度数组转为 0–1 `float32`，再按 `clip → ×255 → rint → uint8` 恢复；另换一组非整数量化点的 0–1 float 输入。完成标准：位置和 shape 不变；用 `int16` 或 float 安全计算误差；报告两次最大误差，并说明原始 uint8 往返为何可精确、任意 0–1 float 量化后为何未必逐元素相同。这只是表示转换，不是增强算法。
