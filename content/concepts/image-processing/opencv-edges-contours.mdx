# 边缘、轮廓与区域测量（Edges & Contours）

本页只解决一个工程问题：**怎样把“哪里可能有边界”的证据与“哪里属于目标”的区域分开，再从可信区域边界得到可解释的测量结果。**

```text
validated grayscale
→ edge evidence
→ inspect edge-map contract and known edge
→ validated binary region mask
→ find external contours
→ inspect contour representation
→ area / perimeter / bounding box
→ filter obvious tiny contours
→ verify known geometry and source protection
→ diagnose failures
```

## 1. 这是什么

**边缘（edge）**是像素强度在空间上明显变化的位置证据。Sobel 保留变化方向与符号；Canny 把候选边界整理成二值 **edge map（边缘图）**。

**区域 mask（region mask）**描述哪些空间位置属于 foreground。白色 `255` 通常表示区域内部，黑色 `0` 表示背景。

**轮廓（contour）**是沿一个二值区域边界排列的二维点序列。它让我们能计算多边形面积、周长和外接矩形。

| 数据 | 当前含义 | 常见契约 | 白色 255 表示什么 |
| --- | --- | --- | --- |
| Sobel response | 某方向的有符号强度变化 | H×W，float32 | 不适用 |
| Canny edge map | 边界证据 | H×W，uint8，0/255 | 边界位置 |
| Binary region mask | 区域归属 | H×W，uint8，0/255 | foreground 内部 |
| Contour | 区域边界点序列 | 常见 N×1×2，整数 `(x,y)` | 不适用 |

最重要的边界是：**edge map 的 255 是边界证据，不是目标区域内部。** 不能因为两个数组都是 H×W、uint8、0/255，就把它们当成同一种数据。

## 4. 核心概念

### 4.1 Sobel：先保留变化方向和符号

本页只用 Sobel 建立工程直觉，不推导 kernel。`dx=1, dy=0` 检查水平方向坐标 `x` 上的强度变化，也就是对竖直边界产生响应；`dx=0, dy=1` 检查 `y` 方向变化。

```python
sobel_x = cv2.Sobel(gray, cv2.CV_32F, dx=1, dy=0, ksize=3)
sobel_y = cv2.Sobel(gray, cv2.CV_32F, dx=0, dy=1, ksize=3)
```

使用 `CV_32F` 是为了保留正值和负值：暗→亮是正响应，亮→暗是负响应。若直接写入 `uint8`，负值无法表达，方向信息会丢失。平坦区域应接近 0；这比只看一张 auto-scaled 图更可信。

对本页左侧 30、右侧 220 的固定阶跃，强度差是 `220-30=190`。当前 3×3 Sobel x 在这个局部阶跃位置的有效权重贡献合计为 4，所以运行后会看到 `4×190=760`：暗→亮为 `+760`，亮→暗为 `-760`。学习时先根据方向预测正负和 flat≈0，再用这条最小数值关系解释实际幅值；当前不需要推导完整 Sobel kernel。

### 4.2 Canny：两个阈值控制连接与保留

```python
edges = cv2.Canny(gray, threshold1=50, threshold2=150)
```

- low threshold（低阈值）帮助决定较弱响应能否在与强边缘连接时保留；
- high threshold（高阈值）标记强边缘候选；
- 本页保持 `low <= high`，并把两者记录为同一实验参数。

当前输出契约必须验证：H×W、`uint8`、values 属于 `{0,255}`。阈值偏低时噪声响应可能大量进入 edge map；偏高时真实阶跃也可能消失。Gaussian 只在噪声确实干扰当前 edge evidence 时作为显式、可比较的预处理，不是 Canny 前必做仪式。

Canny 的 low/high 是边缘候选连接与确认参数；上一页 fixed threshold 则逐像素决定 foreground/background。两者都叫 threshold，但语义不同。

本页不展开非极大值抑制、滞后连接或完整 Canny 推导。

### 4.3 Region mask 才是 findContours 的正式主输入

```python
values = set(np.unique(mask).tolist())
assert mask.ndim == 2
assert mask.dtype == np.uint8
assert values.issubset({0, 255})

snapshot = mask.copy()
contours, hierarchy = cv2.findContours(
    mask,
    cv2.RETR_EXTERNAL,
    cv2.CHAIN_APPROX_SIMPLE,
)
assert np.array_equal(mask, snapshot)
```

当前正式路径使用 H×W、单通道 `uint8` region mask，foreground 为 `255`。OpenCV 也会把非零 `uint8` 值（例如 7）当作 foreground，但这不等于任意 grayscale 都是合法 region mask；本页先把值收敛为 0/255，防止区域语义不清。

当前 Python binding 返回两个值：`contours, hierarchy`。本项目验证路径中 input 未变化，但仍保留 snapshot/assert，不把绑定行为当成忽略 source protection 的理由。float32 或三通道输入在当前正式路径中无效，应在调用前诊断，而不是依赖 traceback。

### 4.4 Contour 的 shape 与坐标

单个轮廓常见 shape 是 `N×1×2`：

- `N` 是保留下来的边界点数量；
- 最后一维两个数是 `(x,y)`；
- 数组访问仍是 `image[y,x]`。

因此轮廓点 `(3,2)` 对应图像位置 `[2,3]`。不能把 contour `(x,y)` 的顺序机械抄成 NumPy `[row,column]`。

本页只用 `RETR_EXTERNAL` 获取最外层边界，只用 `CHAIN_APPROX_SIMPLE` 压缩 contour representation 中水平/竖直直线上的冗余点。矩形可能只保存 4 个 corner points，但这不表示图像边界只有 4 个 raster boundary pixels，也不表示原 binary region 被修改：stored contour points 是压缩后的边界表示，raster boundary pixels 仍属于输入栅格。

带孔区域可能有内部边界；`RETR_EXTERNAL` 只决定“返回哪些 contours”，不会修改输入 binary mask。hole 仍保留在输入数组中，只是当前模式不把 inner boundary 作为独立 contour 返回。hierarchy 细节留到后续，不在这里展开。

### 4.5 Area、perimeter 与 bounding box 回答不同问题

- `cv2.contourArea(contour)`：轮廓多边形围成的几何面积；
- `cv2.arcLength(contour, True)`：闭合轮廓的周长；
- `cv2.boundingRect(contour)`：返回 `(x,y,w,h)` 的轴对齐外接矩形。

外接 ROI 写成 `image[y:y+h, x:x+w]`。这再次体现 contour/bbox 用 `(x,y)`，NumPy slice 用 `[y,x]`。

对 `mask[2:7, 3:11] = 255`，把五个结果放在同一套几何中看：

1. **Raster foreground pixel count**：columns `3,4,5,6,7,8,9,10` 共 8 列，rows `2,3,4,5,6` 共 5 行，所以有 `8×5=40` 个 foreground samples。
2. **Contour polygon coordinate span**：角点从 `x=3` 到 `x=10`，跨度为 7；从 `y=2` 到 `y=6`，跨度为 4，所以 `contourArea=7×4=28`。
3. **Closed perimeter**：同一多边形的闭合周长是 `2×(7+4)=22`。
4. **Bounding rectangle**：它覆盖离散像素坐标 `x=3...10` 和 `y=2...6`，因此是 `(x,y,w,h)=(3,2,8,5)`。
5. **ROI slice**：`image[2:2+5, 3:3+8]`，也就是 `image[2:7, 3:11]`，spatial shape 为 `(5,8)`。

因此 polygon coordinate span `7×4` 不等于 raster coverage `8×5`。二者都正确，只是在描述不同对象：前者测连续多边形，后者数离散像素位置。

### 4.6 Tiny contour filtering 必须公开规则

一个孤立 foreground pixel 是一个离散 foreground sample，所以它确实占据一个 pixel location，`bbox=1×1`。但 `contourArea` 测量的是 contour points 围成的连续二维 polygon area；单个 contour point 无法围成二维区域，因此 `area=0`。三者并不矛盾。

本页可用 `area >= 1` 删除这个**已知合成实验**中的伪目标，但这不是通用阈值：`area=0` 不一定是噪声，小 contour 也不一定是伪目标，真实小目标同样可能被删。正式记录必须包含任务假设、threshold、筛选前后 contour count，以及被删除对象的 area/bbox。

### 4.7 Filtering 与 morphology 都是条件化选择

- 有噪声使 Canny 产生大量 off-edge 响应时，可比较 3×3 Gaussian 前后；
- binary mask 有已知小缺口或孤立点、且结构元素与目标尺度匹配时，可选择 morphology；
- 输入已干净时，不应为了流程整齐固定 blur 或 morphology。

Morphology 会改变 binary region geometry，因此还可能改变 contour count、`contourArea`、perimeter 与 `boundingRect`。它不是“无代价 cleanup”；是否使用必须由任务目标和前后数值证据决定。

## 5. 初学者直觉解释

把 edge map 想成沿边界画的“细线提示”，region mask 想成把目标内部“涂满”，contour 则是沿涂满区域外沿记录的一串 `(x,y)` 点。细线提示可以帮助看边在哪里，却没有自动告诉你线内哪边属于目标；所以轮廓测量主线从已验证的 region mask 出发。

## 6. 必须掌握到什么程度

- 能用 `CV_32F` Sobel 解释暗→亮、亮→暗与 flat response；
- 能记录并判断 Canny low/high、shape、dtype、values、known edge 和 edge count；
- 能区分 edge map、region mask 与 contour；
- 能验证 findContours input/output、contour shape 和 `(x,y)`；
- 能计算并解释 area、perimeter、bbox 与 foreground count；
- 能用透明最小规则过滤明显 tiny contour，并证明 source 未修改；
- 能用统一失败卡诊断输入、阈值、极性、坐标与显示问题。

当前不学习完整 Sobel/Canny 推导、segmentation 理论、contour hierarchy、connected components、convex hull、moments、shape matching、Hough、sub-pixel edge、物理尺寸标定或轮廓跟踪。

## 7. 常见误区

| 误区 | 实际问题 | 当前修正 |
| --- | --- | --- |
| 用 uint8 保存 signed Sobel | 负响应无法表达 | `CV_32F` 并检查关键像素 |
| Canny 阈值越低越“灵敏越好” | 噪声边也会大量进入 | 记录 main/off-edge count |
| edge map 的 255 就是目标内部 | 它表示边界证据 | region mask 单独验证 |
| 任意 grayscale 都能直接找轮廓 | 非零灰度会被视作 foreground | 收敛到 H×W uint8 0/255 |
| contour point 当成 `[row,column]` | contour 是 `(x,y)` | 访问图像时改为 `[y,x]` |
| foreground count 等于 contour area | 离散样本数与多边形面积定义不同 | 同时报告 40 与 28 |
| 轮廓越小越该删 | 小目标可能是真目标 | 公开筛选规则与任务假设 |
| 有孔区域用 `RETR_EXTERNAL` 会返回孔 | 该模式只保留最外层边界 | 记录 retrieval mode |
| 直接在 source 上画轮廓 | 污染测量输入与基准 | `result = source.copy()` |

## 8. Worked Example

四个 checkpoint 可逐段运行。阶跃和矩形都是已知几何合成数据，用来验证数值契约，不是新的图像生成课程。

### Checkpoint 1 — Signed Sobel

```python
import cv2
import matplotlib.pyplot as plt
import numpy as np


dark_to_bright = np.full((7, 11), 30, dtype=np.uint8)
dark_to_bright[:, 5:] = 220
bright_to_dark = np.full((7, 11), 220, dtype=np.uint8)
bright_to_dark[:, 5:] = 30
assert dark_to_bright.shape == bright_to_dark.shape == (7, 11)
assert dark_to_bright.dtype == bright_to_dark.dtype == np.uint8
assert (dark_to_bright.min().item(), dark_to_bright.max().item()) == (30, 220)

sobel_positive = cv2.Sobel(dark_to_bright, cv2.CV_32F, 1, 0, ksize=3)
sobel_negative = cv2.Sobel(bright_to_dark, cv2.CV_32F, 1, 0, ksize=3)
sobel_y = cv2.Sobel(dark_to_bright, cv2.CV_32F, 0, 1, ksize=3)

assert sobel_positive.dtype == np.float32
assert sobel_positive[3, 4] == sobel_positive[3, 5] == 760.0
assert sobel_negative[3, 4] == sobel_negative[3, 5] == -760.0
assert np.max(np.abs(sobel_positive[:, :4])) == 0.0
assert np.max(np.abs(sobel_y)) == 0.0

# 只为显示构造 magnitude mapping；signed response 本身没有被覆盖。
sobel_magnitude_for_display = np.abs(sobel_positive)
assert sobel_magnitude_for_display.min() == 0.0
assert sobel_magnitude_for_display.max() == 760.0
assert sobel_positive[3, 4] == 760.0
```

运行前只需预测暗→亮为正、亮→暗为负、flat≈0。运行后再解释数值：本例差值为 `190`，当前局部阶跃的有效权重贡献合计为 4，所以 `4×190=760`，方向相反便得到 `+760` 与 `-760`。`sobel_y=0` 是因为这个 fixture 沿 row 方向不变。这里不要求手算完整 Sobel kernel。

### Checkpoint 2 — Canny edge-map contract

```python
step_edges = cv2.Canny(dark_to_bright, 50, 150)
assert step_edges.shape == dark_to_bright.shape
assert step_edges.dtype == np.uint8
assert set(np.unique(step_edges).tolist()) == {0, 255}
assert np.count_nonzero(step_edges) == 7
assert np.flatnonzero(np.any(step_edges > 0, axis=0)).tolist() == [4]

rng = np.random.default_rng(7)
noisy = np.full((25, 41), 80, dtype=np.float64)
noisy[:, 20:] = 180
noisy = np.clip(
    noisy + rng.normal(0.0, 8.0, noisy.shape),
    0,
    255,
).astype(np.uint8)

low_edges = cv2.Canny(noisy, 10, 30)
mid_edges = cv2.Canny(noisy, 50, 150)
high_edges = cv2.Canny(noisy, 900, 1000)
smoothed = cv2.GaussianBlur(noisy, (3, 3), 0)
smoothed_edges = cv2.Canny(smoothed, 50, 150)

def edge_counts(edge_map):
    known_main = int(np.count_nonzero(edge_map[:, 19:21]))
    total = int(np.count_nonzero(edge_map))
    off = total - int(np.count_nonzero(edge_map[:, 17:23]))
    return {"total": total, "known main": known_main, "off": off}

assert edge_counts(low_edges) == {"total": 403, "known main": 25, "off": 359}
assert edge_counts(mid_edges) == {"total": 26, "known main": 25, "off": 0}
assert edge_counts(high_edges) == {"total": 0, "known main": 0, "off": 0}
assert edge_counts(smoothed_edges) == {"total": 25, "known main": 25, "off": 0}
```

`known main` 统计理论阶跃相邻的 columns 19–20；`off` 只统计远离 columns 17–22 的响应，把近边界的一像素定位差异留作单独观察。低阈值保留了 359 个远离主边界的响应；中间阈值有 25 个主边界响应和 1 个紧邻响应；极高阈值删除了真实边缘。3×3 Gaussian 在这个固定噪声实验中把输出收敛为 25 个主边缘像素，但这只支持“当前噪声条件下有帮助”，不支持“Canny 前永远要 blur”。

### Checkpoint 3 — Known contour geometry

```python
mask = np.zeros((10, 16), dtype=np.uint8)
mask[2:7, 3:11] = 255
mask_snapshot = mask.copy()

contours, hierarchy = cv2.findContours(
    mask,
    cv2.RETR_EXTERNAL,
    cv2.CHAIN_APPROX_SIMPLE,
)
assert np.array_equal(mask, mask_snapshot)
assert len(contours) == 1

contour = contours[0]
points = contour.reshape(-1, 2)
expected_points = {(3, 2), (3, 6), (10, 6), (10, 2)}
assert contour.shape == (4, 1, 2)
assert {tuple(point) for point in points.tolist()} == expected_points
assert mask[2, 3] == 255  # contour (x=3,y=2) → image[y=2,x=3]

foreground_pixels = int(np.count_nonzero(mask))
area = float(cv2.contourArea(contour))
perimeter = float(cv2.arcLength(contour, True))
x, y, w, h = cv2.boundingRect(contour)
roi = mask[y:y+h, x:x+w]

assert foreground_pixels == 40
assert area == 28.0
assert perimeter == 22.0
assert (x, y, w, h) == (3, 2, 8, 5)

```

`CHAIN_APPROX_SIMPLE` 把当前轴对齐矩形的 contour representation 压缩成四个角点；这四个 stored points 不等于四个 raster boundary pixels，也没有修改原 mask。统一核对结果为：foreground count `8×5=40`，polygon area `7×4=28`，closed perimeter `2×(7+4)=22`，bounding rectangle `(3,2,8,5)`，对应 ROI `mask[2:7,3:11]` 的 spatial shape `(5,8)`。

## 10. Practice

Practice 可与 Evidence 共用同一 notebook/report；下面共 10 个任务，按明确完成标准生成可复用证据，不需要重复做两套实验。

### 理解检查

1. **手判 step edge**：给定左 30、右 220 的阶跃，指出边界位置与暗→亮方向。完成标准：指出边界位于 columns 4/5 之间，不能把整块亮区域叫作 edge。

2. **Sobel 正负方向**：运行前预测暗→亮、亮→暗的 Sobel x 符号和 flat≈0；运行后记录实际响应。完成标准：先写出正、负、零的方向判断，再用 `4×(220-30)=760` 解释为何本例得到 `+760` 与 `-760`，并说明 `CV_32F` 保留方向。

3. **Flat region**：解释并验证平坦区和当前 Sobel y 为什么为 0。完成标准：报告 max abs=0，并把它连接到对应方向没有强度变化，而非“算子失效”。

4. **三种对象分类**：把 `CV_32F Sobel response`、Canny output、region mask 与 `(4,1,2)` 点数组分类。完成标准：明确 Canny 255 是边界、mask 255 是内部、contour 点是 `(x,y)`。

### 数值练习

5. **Canny low/high failure**：运行 low/mid/high 三组参数。完成标准：记录 shape/dtype/values、known edge、main/off-edge count，并分别写 too-low 与 too-high 五字段失败卡。

6. **Contour representation**：对 known rectangle 记录 contour count、`N×1×2` 和四个点。完成标准：得到 `(4,1,2)`，解释 N 与最后一维，不只打印数组。

7. **坐标换序**：用 contour point `(3,2)` 核对 `image[2,3]`，再写 bbox ROI。完成标准：明确 `(x,y)` → `[y,x]`，写出 `image[y:y+h,x:x+w]`。

8. **矩形测量**：先推导再验证 area、closed perimeter、bbox 与 ROI shape。完成标准：写出 polygon span `7×4`、`2×(7+4)=22`、离散 coverage `8×5`、`(3,2,8,5)` 与 `image[2:7,3:11] → (5,8)`，说明它们回答不同问题。

9. **Pixel count vs polygon area**：解释 foreground count 40 与 contour area 28。完成标准：分别写出 8×5 离散样本和 7×4 连续坐标跨度，不能归因于 OpenCV 错误。

### 视觉小练习
