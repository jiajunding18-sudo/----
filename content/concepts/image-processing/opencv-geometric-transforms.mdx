# 缩放、旋转与仿射变换（Geometric Transforms）

本页把 Stage 1 的二维矩阵直觉落到图像上。核心流程不是“调用一个 warp 函数”，而是：

```text
validated source
→ inspect H / W / channel contract
→ define coordinate transform
→ predict known points
→ choose interpolation
→ choose output canvas / border
→ run resize or warpAffine
→ verify shape / coordinates / display
→ diagnose mismatch
```

这里的几何矩阵主要描述**位置和坐标之间的关系**，不是把像素颜色直接乘了一下。图像 warp 还要决定每个输出像素去输入图的哪里取值，因此结果共同取决于 coordinate transform、sampling、interpolation 和 output canvas。

## 1. 这是什么

**几何变换（geometric transform）**改变像素在图像平面中的位置关系。当前只学习四类基础操作：

- **缩放（resize / scaling）**：改变输出宽高；
- **旋转（rotation）**：围绕指定中心转动坐标；
- **平移（translation）**：把坐标整体移动 $(t_x,t_y)$；
- **仿射变换（affine transform）**：用线性部分加平移组合缩放、旋转、剪切和平移。

对一个二维点 $(x,y)$，先把输入记为 $p_h=[x,y,1]^T$，输出记为 $p'=[x',y']^T$。OpenCV 的 $2\times3$ affine matrix 满足：

$$
M=
\begin{bmatrix}
a_{11} & a_{12} & t_x\\
a_{21} & a_{22} & t_y
\end{bmatrix}.
$$

$$
p'=Mp_h.
$$

左侧 $2\times2$ 部分改变方向、尺度或剪切，最后一列提供平移或旋转中心补偿。这里借用了常数 1 来写计算，不展开完整齐次坐标理论。

## 2. 为什么机器视觉需要它

### 为什么现在学

你已经在 `math.linear-transforms` 中让矩阵作用于二维点，也已经能通过 `opencv.io-color` 获得经过验证的真实图像数组。现在要连接两者：既预测一个点去哪里，也检查完整图像怎样被重新采样到有限的输出画布上。

### 在机器视觉中会在哪里使用

- 统一不同尺寸输入，准备后续批处理或模型输入；
- 旋转或平移受控测试图，检查算法对位置变化的反应；
- 用 affine 对应点修正简单平面形变；
- 为后续 `dl.augmentation` 建立“变换不能破坏标签语义”的坐标基础；
- 为以后正式学习 `geometry.homography` 区分 affine 与 perspective 的边界。

本页不表示已经会图像配准、相机标定或投影几何。

## 4. 核心概念

### 4.1 NumPy shape 与 OpenCV size 的顺序不同

对于彩色图像：

```python
height, width = image.shape[:2]
```

NumPy 的空间 shape 是 `(height, width)`，但 OpenCV 的 `dsize` 参数写成 `(width, height)`：

```python
new_width = 12
new_height = 8

resized = cv2.resize(
    image,
    (new_width, new_height),
    interpolation=cv2.INTER_LINEAR,
)

assert resized.shape[:2] == (new_height, new_width)
```

若输入是 `H×W×C`，目标尺寸为 `new_width×new_height`，则：

$$\mathrm{scale}_x=\frac{\mathrm{new\ width}}{\mathrm{width}}.$$

$$\mathrm{scale}_y=\frac{\mathrm{new\ height}}{\mathrm{height}}.$$

像素宽高最终必须是整数。为了让实验可重复，本页在从 factor 自行计算 `dsize` 时固定使用 Python `round`，再显式把整数 `(new_width, new_height)` 传给 OpenCV：

```python
width, height = 10, 7
scale_x, scale_y = 1.25, 1.5

new_width = round(width * scale_x)   # round(12.5) == 12
new_height = round(height * scale_y) # round(10.5) == 10
assert (new_width, new_height) == (12, 10)
```

Python 的 `round` 在恰好位于两个整数中间时取最近的偶数，所以这里是 12 和 10，不是含糊的“差不多取整”。在当前 OpenCV 行为实验中，省略 `dsize` 而使用 `fx=1.25, fy=1.5` 也得到 shape `(10,12)`；正式证据仍优先显式计算并传入 `dsize=(12,10)`，使取整契约由代码清楚表达。

把 `(new_width, new_height)` 写反通常不会报错，却会得到错误的 output shape 和 aspect ratio。因此本页固定同时记录 input shape、dsize 和 actual output shape。

### 4.2 坐标变化之后为什么需要 interpolation

图像数组只在整数像素位置保存数值，但缩放或旋转后，输出像素所对应的输入位置经常是小数，例如 $(3.4,2.7)$。**插值（interpolation）**决定怎样从附近输入像素得到该位置的输出值。

当前只使用：

| 方法 | 当前工程直觉 | 本页用途 |
| --- | --- | --- |
| `INTER_NEAREST` | 取最近的输入像素，不混合邻近值 | 离散标记、标签或已知点核对 |
| `INTER_LINEAR` | 用附近像素形成平滑的基础估计 | 一般放大与 affine warp |
| `INTER_AREA` | 根据像素区域关系重采样 | 常用于缩小图像 |

这些是任务相关选择，不是“永远最优”的排名。本页不推导 cubic、Lanczos 或完整采样理论。

### 4.3 Coordinate transform 与 image warp 不是同一步

学习者通常用 matrix 表达 forward mapping：

```text
输入点 (x, y) 应该移动到输出点 (x', y')
```

但生成完整输出图时，程序需要逐个回答：

```text
当前输出像素应该去输入图的哪里取值？
```

OpenCV 的 warp 函数在默认使用 forward matrix 时，会为实际采样处理相应的反向映射，再用 interpolation 取得像素值。当前只需建立这层直觉：**点的 forward prediction 用于验证；图像生成需要 reverse sampling。** 不要求手动求逆，也不学习完整 `WARP_INVERSE_MAP` 体系。

### 4.4 Rotation：中心、角度、尺度与 2×3 matrix

```python
height, width = source.shape[:2]
center = ((width - 1) / 2.0, (height - 1) / 2.0)
angle_degrees = 90.0
scale = 1.0

rotation_matrix = cv2.getRotationMatrix2D(
    center,
    angle_degrees,
    scale,
)

assert rotation_matrix.shape == (2, 3)
```

`center` 按 `(x,y)` 书写；`angle` 使用度；`scale=1` 表示不额外缩放。matrix 左侧 $2\times2$ 是带 scale 的旋转部分，最后一列补偿中心，使 center 变换后仍保持原坐标。

这里必须区分两个同名但职责不同的量：

- **resize scale**：`scale_x = new_width / width`、`scale_y = new_height / height`，直接决定 resize 的输出宽高；
- **rotation scale**：`getRotationMatrix2D(center, angle, scale)` 中围绕同一 center 施加的各向同性几何缩放，是 rotation affine matrix 的一部分。

例如 `scale=0.5` 会让 marker 到 center 的距离缩短为一半，但 `warpAffine` 返回的数组 shape 仍由单独传入的 `dsize` 决定，不会自动减半。它不等于“直接指定 `cv2.resize` 的输出尺寸”。

OpenCV 当前约定正角度为逆时针，但图像的 y 轴通常向下，初学者容易把数学草图和屏幕视觉混淆。本页不只背方向口号：用一个不在中心上的已知 marker 预测并核对实际输出。

### 4.5 Translation：为什么是 2×3

平移矩阵写成：

```python
translation_matrix = np.float32([
    [1, 0, tx],
    [0, 1, ty],
])
```

- 左侧 `[[1,0],[0,1]]` 是 identity，保持方向和尺度；
- `tx` 改变 x，也就是 column 方向；
- `ty` 改变 y，也就是 row 方向；
- 普通 $2\times2$ 线性矩阵会把原点留在原点，不能单独表达“所有点整体移动”，所以 OpenCV affine matrix 还需要最后一列。

例如 $(3,2)$ 经过 `tx=4, ty=1` 后应得到 $(7,3)$。

### 4.6 三对点定义最小 affine transform

`cv2.getAffineTransform` 使用三对二维对应点：

```python
src_points = np.array(
    [[1, 1], [9, 1], [1, 5]],
    dtype=np.float32,
)
dst_points = np.array(
    [[2, 1], [8, 2], [2, 6]],
    dtype=np.float32,
)

assert src_points.shape == (3, 2)
assert dst_points.shape == (3, 2)
assert src_points.dtype == np.float32
assert dst_points.dtype == np.float32

affine_matrix = cv2.getAffineTransform(src_points, dst_points)
assert affine_matrix.shape == (2, 3)
```

source 三个点还必须形成一个有效三角形，也就是**不能共线（non-collinear）**。三个非共线点提供二维中的两个独立方向；若三个点都落在同一直线上，就缺少另一个方向的信息，无法唯一确定一般 affine transform。

```python
collinear_points = np.array([[0, 0], [1, 1], [2, 2]], dtype=np.float32)
valid_triangle = np.array([[0, 0], [2, 0], [0, 2]], dtype=np.float32)
```

当前 OpenCV 行为实验对上面的退化共线输入返回了全零 `2×3` matrix，并没有抛异常；这不是“变换有效”的证明，也不应依赖该返回行为。应在调用前先检查输入几何是否构成非退化三角形。当前只要求理解三对点建立 source→destination 的 affine 关系，不要求手工解六个参数或证明秩条件。

Affine 会保持直线与平行关系：同一直线上的点变换后仍共线，两条平行线的方向变换后仍平行。它一般不保证长度、角度或面积保持；只有当具体 affine 属于更特殊的变换类别时，这些量才可能保持。

### 4.7 Output canvas 与 clipping

`cv2.warpAffine(source, matrix, dsize)` 只生成指定大小的输出画布。落在画布外的内容不会自动让画布无限扩张；采样落到输入边界外时，则由 border 规则决定输出值。

扩大 `dsize` 只增加正方向上的输出范围，不会自动移动输出坐标原点 `(0,0)`。若 marker 经变换落在负 x 或负 y，仅增大 width / height 仍可能完全看不到；此时还要调整 affine matrix 的 translation，把负坐标内容移回可见范围。**扩大画布**与**调整输出坐标位置**是两个不同操作。

还要区分两个边界现象：

- **clipping**：有效内容的输出坐标落在 canvas 外，因此不显示；
- **border fill**：某个输出位置存在，但 reverse sampling 找不到有效输入位置，因此使用指定填充值。

本页示例使用 `BORDER_CONSTANT` 和 `borderValue=(0,0,0)`；输出黑边是人工指定的 border fill，不是原图自带黑像素、clipping 产生的颜色，也不是 interpolation 自动生成的黑色。本页不展开其他 BorderTypes。

## 5. 初学者直觉解释

把输入图想成一张带网格的透明片：

1. matrix 先说明透明片上的坐标应该移到哪里；
2. output canvas 决定最终只保留哪一块有限区域；
3. 对输出网格的每个格点，warp 回到输入透明片寻找来源；
4. 来源落在格点之间时用 interpolation；落到输入外面时用 border 规则。

所以“marker 的坐标预测正确”与“输出像素逐元素相同”不是同一个要求。前者验证几何，后者还受 interpolation、border 和编码/显示契约影响。

## 6. 必须掌握到什么程度

当前 `targetDepth: master` 表示能独立完成并诊断基础几何变换：

- 从 `(H,W,C)` 正确构造 OpenCV `(W,H)`；
- 解释并比较 nearest、linear、area 的最低限度用途；
- 生成 rotation、translation 和三点 affine 的 $2\times3$ matrix；
- 预测已知点，核对输出坐标与合理容差；
- 设置 output canvas，识别 clipping 与 border；
- 保留 source，通过 shape、matrix、坐标和可信显示诊断常见错误。

**当前不学习**：Perspective Transformation、homography、`warpPerspective`、完整齐次坐标、相机模型、标定、图像配准、remap、polar transform、插值公式推导或完整采样理论。

## 7. 常见误区

| 误区 | 为什么危险 | 当前检查 |
| --- | --- | --- |
| `shape[:2]` 直接作为 `dsize` | H/W 与 W/H 顺序相反 | 断言 actual output shape |
| matrix 在改变像素颜色 | 混淆坐标与采样 | 分开记录 point prediction 与 interpolation |
| 只看“好像旋转了” | 方向或中心错仍可能看似合理 | 用非中心 marker 做坐标核对 |
| 输出内容消失就是 matrix 错 | 可能只是 canvas 太小 | 同一 matrix 对比两种 dsize |
| affine 三点用整数或错误 shape | API contract 不清，错误难定位 | 断言 `(3,2)` 与 `float32` |
| `INTER_LINEAR` 永远最好 | 不同任务需要不同数值语义 | 对离散标记、一般图像和缩小分别说明 |
| 变换后直接覆盖 source | 丢失基准，无法判断变化来源 | source/original/result 分离并最终断言 |

## 8. Worked Example

以下实验使用程序生成的 `7×11` 非方形 BGR 图像。非方形输入会暴露 width/height 写反；红色和绿色 marker 提供已知坐标。它不是新的图像生成课程，只是稳定、可重复的几何测试输入。

### Checkpoint 1：Resize、H/W 与 interpolation

```python
import cv2
import matplotlib.pyplot as plt
import numpy as np


def make_marker_image():
    image = np.full((7, 11, 3), 24, dtype=np.uint8)
    image[:, ::2] = [48, 48, 48]
    image[2, 3] = [0, 0, 255]   # BGR red marker，几何点 (x,y)=(3,2)
    image[5, 8] = [0, 255, 0]   # BGR green marker，几何点 (8,5)
    image[1, 1] = [255, 0, 0]   # 三点 affine 的 BGR blue anchor
    image[1, 9] = [0, 255, 255] # 三点 affine 的 BGR yellow anchor
    image[5, 1] = [255, 0, 255] # 三点 affine 的 BGR magenta anchor
    return image


source = make_marker_image()
original = source.copy()
height, width = source.shape[:2]
assert (height, width) == (7, 11)

new_width = 22
new_height = 14
scale_x = new_width / width
scale_y = new_height / height

nearest = cv2.resize(
    source,
    (new_width, new_height),
    interpolation=cv2.INTER_NEAREST,
)
linear = cv2.resize(
    source,
    (new_width, new_height),
    interpolation=cv2.INTER_LINEAR,
)
area_small = cv2.resize(
    source,
    (6, 4),
    interpolation=cv2.INTER_AREA,
)

assert nearest.shape == (14, 22, 3)
assert linear.shape == (14, 22, 3)
assert area_small.shape == (4, 6, 3)
assert scale_x == 2.0 and scale_y == 2.0

# 非整数 scale：本页显式使用 Python round，再传入整数 dsize。
scale_probe = np.zeros((7, 10), dtype=np.uint8)
probe_scale_x, probe_scale_y = 1.25, 1.5
probe_width = round(scale_probe.shape[1] * probe_scale_x)
probe_height = round(scale_probe.shape[0] * probe_scale_y)
explicit_probe = cv2.resize(
    scale_probe,
    (probe_width, probe_height),
    interpolation=cv2.INTER_NEAREST,
)
implicit_probe = cv2.resize(
    scale_probe,
    None,
    fx=probe_scale_x,
    fy=probe_scale_y,
    interpolation=cv2.INTER_NEAREST,
)
assert (probe_width, probe_height) == (12, 10)
assert explicit_probe.shape == implicit_probe.shape == (10, 12)

# 用已知标量模式记录三种 interpolation 的代表数值。
two_by_two = np.array([[0, 255], [255, 0]], dtype=np.uint8)
nearest_probe = cv2.resize(two_by_two, (5, 5), interpolation=cv2.INTER_NEAREST)
linear_probe = cv2.resize(two_by_two, (5, 5), interpolation=cv2.INTER_LINEAR)
assert nearest_probe[1, 1] == 0
assert linear_probe[1, 1] == 46
assert np.count_nonzero(nearest_probe != linear_probe) == 21

checkerboard = np.array(
    [
        [0, 255, 0, 255],
        [255, 0, 255, 0],
        [0, 255, 0, 255],
        [255, 0, 255, 0],
    ],
    dtype=np.uint8,
)
area_probe = cv2.resize(checkerboard, (2, 2), interpolation=cv2.INTER_AREA)
assert np.array_equal(area_probe, np.full((2, 2), 128, dtype=np.uint8))

# 故意错误：把 OpenCV dsize 写成 (height, width)。
swapped = cv2.resize(source, (new_height, new_width))
diagnosis = {
    "input": {"source shape": source.shape, "dsize": (new_height, new_width)},
    "expected": {"output shape": (new_height, new_width, 3)},
    "actual": {"output shape": swapped.shape},
    "reason": "OpenCV dsize 是 (width, height)，不是 NumPy 的 (height, width)。",
    "correction": "传入 (new_width, new_height)，再断言 shape[:2]。",
}
print(diagnosis)
assert swapped.shape == (22, 14, 3)
```

```python
def report_diagnosis(case, input_contract, expected, actual, reason, correction):
    print("case:", case)
    print("input:", input_contract)
    print("expected:", expected)
    print("actual:", actual)
    print("reason:", reason)
    print("correction:", correction)


report_diagnosis(
    "width / height 写反",
    {"source shape": source.shape, "dsize": (new_height, new_width)},
    {"shape": (new_height, new_width, 3)},
    {"shape": swapped.shape},
    "把 NumPy shape 顺序直接传给了 OpenCV dsize。",
    "显式命名 new_width/new_height，并断言 output.shape[:2]。",
)

report_diagnosis(
    "output canvas 太小",
    {"green point": (8, 5), "translation": (tx, ty), "dsize": (width, height)},
    {"predicted point": (12, 6), "visible": True},
    {"predicted point": (12, 6), "visible": False},
    "x=12 已超出原画布 0..10；内容消失不是 warpAffine 程序错误。",
    "根据任务扩大 output canvas，或调整 transform 的平移部分。",
)

report_diagnosis(
    "negative-coordinate canvas misconception",
    {"point": (1, 1), "translation": (-3, 0), "larger dsize": (width + 10, height + 5)},
    {"visible coordinate condition": "x>=0 and y>=0"},
    {"predicted point": tuple(negative_prediction), "marker visible": False},
    "扩大 dsize 只增加正方向范围，输出原点仍为 (0,0)，所以 x=-2 仍被 clipping。",
    "给 affine matrix 的 translation 增加输出 offset，使预测坐标进入 x>=0、y>=0。",
)

wrong_points = np.array([[1, 1, 1], [9, 1, 1], [1, 5, 1]], dtype=np.int32)
report_diagnosis(
    "affine point contract 错误",
    {"shape": wrong_points.shape, "dtype": wrong_points.dtype},
    {"shape": (3, 2), "dtype": np.dtype(np.float32)},
    {"shape": wrong_points.shape, "dtype": wrong_points.dtype},
    "getAffineTransform 当前输入应是三对二维 float32 点。",
    "重建为 np.array([[x,y], ...], dtype=np.float32)。",
)
assert wrong_points.shape != (3, 2)
assert wrong_points.dtype != np.float32

report_diagnosis(
    "affine source points 共线",
    {"src_points": collinear_points.tolist(), "shape": collinear_points.shape},
    {"source geometry": "non-collinear triangle"},
    {"signed twice area": float(signed_twice_area(collinear_points)), "matrix": degenerate_matrix.tolist()},
    "三个 source points 只提供同一直线方向，无法唯一约束一般二维 affine transform。",
    "改用三个非共线 source points，并在调用前检查三角形面积不接近 0。",
)

wrong_direction_prediction = transform_point(
    cv2.invertAffineTransform(translation_matrix),
    point,
)
report_diagnosis(
    "mapping direction 与预期不一致",
    {"point": point, "matrix used": "destination-to-source inverse"},
    {"forward source-to-destination": (7.0, 3.0)},
    {"predicted": tuple(wrong_direction_prediction)},
    "用于点预测的 matrix 方向写反；图像 warp 的内部反向采样不等于手工改用 inverse 做 forward prediction。",
    "先标记 source→destination，再用原 translation matrix 预测点。",
)

assert np.array_equal(source, original)
```

这六类报告都按 **input → expected → actual → reason → correction** 回答。失败诊断不能只保留 traceback，也不能因为图像“还能显示”就跳过 shape、坐标、输入几何和画布检查。
