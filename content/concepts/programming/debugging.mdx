# 调试与问题定位（Debugging and Problem Localization）

调试不是“试几个改动”。它是一项小型实验：控制变量，保留证据，让错误稳定地从出现走向消失。

## 1. 这是什么

**调试（debugging）**是定位实际行为与预期行为差异的过程。最小复现保留触发错误所需的最少输入和步骤；traceback 展示异常传播路径；观察点可以是日志、打印、断点或断言；回归检查确认修复没有破坏原本正确的行为。

## 2. 为什么机器视觉需要它

“图像是黑的”可能是路径读错、数组为空、通道理解错误、显示范围错误或真实曝光不足。若同时改路径、参数和环境，即使现象消失，也不知道哪个变化有效，更无法信任后续测量。

## 3. 前置知识

硬前置是 Python 核心语法，因为你需要追踪变量与控制流。推荐掌握开发环境，以便检查解释器和依赖，而不是把所有导入错误归咎于代码。

## 4. 核心概念

一个可复用的顺序是：

1. 写清**预期**与**实际现象**；
2. 固定输入、命令、工作目录和解释器，建立最小复现；
3. 阅读第一条与自己代码有关的 traceback；
4. 提出一个可证伪假设；
5. 增加最小观察，只改变一个因素；
6. 修复后重跑失败案例与正常案例；
7. 记录根因与防复发检查。

## 5. 初学者直觉解释

把调试想成排查一条断路：从“灯不亮”不能直接断定灯泡坏了。你要确认电源、开关、导线和灯泡，每次测一个点。随机换全部零件也许能亮，但没有产生可迁移的知识。

## 6. 必须掌握到什么程度

你需要能独立定位路径、错误解释器/导入和坏输入三类常见故障；会保留 traceback，打印值、类型、形状或路径等关键观察；修复后同时复测失败输入与一个已知正常输入。暂时不要求性能剖析或底层调试器技巧。

## 7. 常见误区

- 只截 traceback 最后一行，丢失调用位置与上下文。
- 同时改多处，无法判断因果。
- 搜索错误文本后直接粘贴命令，不核对环境是否相同。
- 用 `try/except` 隐藏症状，而没有修复根因。
- 只重跑曾失败案例，不验证正常案例仍然正确。

## 8. Worked Example：OpenCV 读图为何得到 `None`

```python
from pathlib import Path

import cv2


def load_image(path_text: str):
    path = Path(path_text).resolve()
    print("cwd:", Path.cwd())
    print("resolved input:", path)
    print("exists:", path.exists())

    image = cv2.imread(str(path))
    if image is None:
        raise ValueError(f"OpenCV 无法解码图像：{path}")
    print("shape:", image.shape, "dtype:", image.dtype)
    return image
```

现象是 `image is None`。假设 A：路径不存在；`exists()` 可证伪。若文件存在，假设 B：内容不是 OpenCV 能解码的图像；换一张已知有效的小图或检查文件来源。不要在验证前同时重装 OpenCV和改路径。

## 9. Active Recall 主动回忆

1. 症状、触发条件和根因有什么区别？
2. 为什么一个假设必须能够被证伪？
3. traceback 中应先找哪一处与你的代码相关的位置？
4. 修复坏路径后，为什么还要测试有效路径？
5. 哪些观察可以区分“未安装包”和“使用了错误解释器”？

## 10. Practice 练习

制作三张故障卡，每次只改变一个条件：

1. 路径卡：把文件名改错，记录解析路径与存在性。
2. 环境卡：用没有 OpenCV 的解释器运行，记录 `sys.executable` 和完整导入错误。
3. 输入卡：把文本文件改名为 `.jpg`，记录“存在但无法解码”的证据。

每张卡都写：预期、现象、最小步骤、首个假设、观察、结论、修复、正常案例回归。

## 11. 实际使用

在 Pixel Lab 中主动运行一个不存在的输入路径。程序必须快速失败并显示解析后的路径。修复后，再运行有效的手机照片或生成图，确认读取和保存仍然成功。

## 12. Mastery Evidence 掌握证据

选择一张故障卡提交完整日志，其中至少包含一个被证伪的假设。用自己的话区分症状、触发条件与根因，并说明新增的路径检查或环境记录如何防止复发。只提交最终代码和“已解决”不合格。

## 13. 后续复用与复习

数组维度、颜色通道、相机连接、训练损失和部署性能都需要相同的方法。24 小时后用空白模板复述调试顺序；7 天后让自己或同伴注入一个未知故障，只依据日志定位。
