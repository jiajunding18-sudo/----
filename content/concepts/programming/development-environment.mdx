# 开发环境与依赖管理（Development Environment and Dependency Management）

环境不是“电脑里装过 Python 就行”，而是一组能被记录、检查和重建的运行条件。

## 1. 这是什么

**Python 解释器（interpreter）**执行源码；**包（package）**提供可导入的代码；`pip` 安装包；**虚拟环境（virtual environment）**为一个项目提供独立解释器入口和包目录。`.venv` 是可重建产物，不是学习成果本身。

## 2. 为什么机器视觉需要它

OpenCV、NumPy 和深度学习库会持续演进。同名的 `python` 与 `pip` 可能来自不同安装。如果不记录解释器与依赖，今天能运行的实验换一台电脑就无法验证，也无法判断差异来自算法还是环境。

## 3. 前置知识

硬前置是“计算机、文件与终端”：需要知道命令在哪个目录执行、进程使用哪个文件。推荐已经能运行简单 Python 脚本。

## 4. 核心概念

- 激活环境主要是调整命令查找路径；它不是安装 Python 的魔法步骤。
- `python -m pip` 明确让当前 `python` 运行其对应的 pip，比裸用 `pip` 更可诊断。
- `sys.executable` 给出当前进程的解释器路径。
- 依赖记录描述“需要安装什么”；`.venv` 目录本身通常不应跨机器复制。
- 可复现不是保证所有机器字节级相同，而是让关键版本、命令和输入条件可检查。

## 5. 初学者直觉解释

把每个项目的虚拟环境想成独立工具箱：工具名称可能相同，但版本和位置属于这个箱子。激活只是把这个工具箱放到手边；`sys.executable` 则是查看手里拿的工具到底来自哪个箱子。

## 6. 必须掌握到什么程度

你需要能在 Windows PowerShell 中创建环境、确认解释器、安装一个直接依赖、导出记录并重建；能诊断最常见的“装了却 import 不到”。暂时不要求掌握 Conda、容器、锁文件求解或跨平台二进制构建。

## 7. 常见误区

- 看到终端前缀 `(.venv)` 就认定环境正确；仍应检查 `sys.executable`。
- 用一个 Python 的 `pip` 安装，再用另一个 Python 运行。
- 把 `.venv` 当作唯一备份，却没有依赖说明和重建步骤。
- 每次报错都重装全部软件，导致原始问题现场消失。
- 为解决激活策略问题而永久放宽整台电脑的安全设置；可以直接调用环境内解释器。

## 8. Worked Example：创建并证明最小环境

在 Pixel Lab 根目录运行：

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -c "import sys; print(sys.executable); print(sys.version)"
python -m pip install opencv-python
python -c "import cv2; print(cv2.__version__)"
python -m pip freeze > requirements.txt
```

如果 PowerShell 不允许激活，不需要绕过策略；直接使用：

```powershell
.\.venv\Scripts\python.exe -m pip install opencv-python
.\.venv\Scripts\python.exe -c "import cv2, sys; print(sys.executable); print(cv2.__version__)"
```

关键证据是解释器路径位于项目 `.venv`，并且安装与运行都由同一解释器发起。

## 9. Active Recall 主动回忆

1. 虚拟环境隔离的主要对象是什么？
2. 为什么推荐 `python -m pip` 而非只写 `pip`？
3. 激活失败是否等于虚拟环境无法使用？
4. 哪个输出能直接证明当前进程使用的解释器？
5. 为什么复制 `.venv` 不等于可靠的环境说明？

## 10. Practice 练习

1. 记录激活前后 `sys.executable`，解释变化。
2. 关闭终端后重新打开，先预测 `python` 指向哪里，再检查。
3. 新建第二个空环境，尝试 `import cv2`，保留失败现场；再用正确解释器安装并复测。
4. 在确认项目源码与输入已备份后，删除这个练习用 `.venv`，按记录重建。不要删除未知目录。

## 11. 实际使用

为 Pixel Lab 留下 `requirements.txt` 和 README 中的三步重建命令。运行项目时同时记录 Python 与 OpenCV 版本，使后续图像读写结果能关联到明确环境。

## 12. Mastery Evidence 掌握证据

提交：重建前后的命令记录；`requirements.txt`；`sys.executable`、Python 和 OpenCV 版本；一次错误解释器导致导入失败的“现象—假设—检查—修复—复测”记录。环境恰好能运行一次不算掌握。

## 13. 后续复用与复习

NumPy、Jupyter、PyTorch 和项目交付都会依赖同一环境模型。24 小时后不用笔记解释安装与运行为何可能错位；7 天后从空环境按记录重建 Pixel Lab 并比较版本。
