# Linux 与命令行最小基础（Minimal Linux and Command-Line Basics）

本单元目标是“读得懂、能对照、需要时能运行”，不是安装 Linux、管理服务器或背完整命令表。Stage 0 对该节点的目标深度是 `understand`。

## 1. 这是什么

**Linux** 是操作系统内核及其周边系统的共同基础；不同发行版提供不同桌面与软件管理方式。**终端（terminal）**是文字界面窗口，**shell**（常见为 Bash）读取命令并启动进程。WSL 是 Windows 中可选的 Linux 环境，但不是本阶段必须安装的前置。

早期需要认识：

- `/` 是文件系统根目录，`/home/name` 常是用户 home；
- `/` 也是路径分隔符，路径通常区分大小写；
- `~` 表示当前用户 home，`.` 表示当前目录，`..` 表示父目录；
- 命令名、参数和选项由空格分隔；成功命令可能没有输出。

## 2. 为什么机器视觉需要它

OpenCV、深度学习、点云库和服务器训练资料常给出 Linux 命令。若把 `.venv\Scripts\python.exe` 原样复制到 Linux，或忽略大小写，失败来自平台表达而非算法。理解最小差异可以让你先诊断环境，再判断代码。

## 3. 前置知识

硬前置只有“计算机、文件与终端”。本页不会要求 Git、管理员权限、软件安装、网络服务或 shell 编程。没有 WSL/Linux 也可以先达到路线要求的 `understood`，但若以后要标记 `mastered`，应补真实环境运行证据。

## 4. 核心概念

| 目的 | Linux shell | PowerShell | 要观察的事实 |
|---|---|---|---|
| 当前目录 | `pwd` | `Get-Location` | 相对路径的起点 |
| 列出文件 | `ls -la` | `Get-ChildItem -Force` | 隐藏项、实际名称与大小写 |
| 切换目录 | `cd path` | `Set-Location path` | 命令后的工作目录 |
| 创建目录 | `mkdir -p output` | `New-Item -ItemType Directory output` | 目标解析后的完整位置 |
| 定位命令 | `which python3` | `Get-Command python` | 实际启动的解释器 |
| 查看进程 | `ps -ef` | `Get-Process` | 是否仍有程序在运行 |

Linux 虚拟环境解释器常位于 `.venv/bin/python`，Windows 常位于 `.venv\Scripts\python.exe`。两者表达相同职责，但路径不能直接互换。

## 5. 初学者直觉解释

把 Linux shell 和 PowerShell 想成两种实验室工作语言：文件、目录、进程这些对象没有变，但动词、路径写法和大小写规则不同。理解对象与作用，再查对应命令，比背一串缩写更可靠。

## 6. 必须掌握到什么程度

达到 `understand` 时，你应能阅读一段五到十行的 Linux 运行说明，指出工作目录、解释器、输入和输出，翻译成等价 PowerShell 步骤，并识别大小写与路径差异。若环境可用，再实操 `pwd / ls / cd / mkdir / which / python3 / ps`。不学习 `sudo`、权限管理、服务、网络、磁盘分区或复杂管道。

## 7. 常见误区

- 把终端、shell、Linux 当作同一个东西。
- 认为 Windows 的 `C:\...` 在 Linux 中仍是通用绝对路径。
- 忽略大小写，认为 `Input.jpg` 与 `input.jpg` 一定是同一文件。
- 看到网上命令就连同提示符 `$` 一起复制。
- 为完成入门练习使用管理员权限；本页命令都应在普通用户和明确练习目录中执行。
- 没有 Linux 环境却伪造运行截图；命令推演与真实运行必须分别标记。

## 8. Worked Example：翻译 Pixel Lab 运行链

Linux/WSL 可用时，在你明确创建的 Pixel Lab 练习目录中运行：

```bash
pwd
ls -la
python3 --version
which python3
python3 -m venv .venv
./.venv/bin/python -c "import sys; print(sys.executable)"
./.venv/bin/python src/main.py images/input.pgm
ps -ef
```

观察顺序是：先确认位置和文件，再确认 Python，最后运行脚本并检查进程。Windows 对应的最后解释器路径是 `.\.venv\Scripts\python.exe`。不要为了命令形式一致而修改程序逻辑。

没有 Linux/WSL 时，建立三列表格：Linux 命令、PowerShell 对应命令、预期可观察事实。对每行写出“若工作目录错误会看到什么”，并明确标注“尚未在 Linux 实机验证”。

## 10. Practice 练习

### 有 Linux/WSL 环境

1. 在个人练习目录中建立 `pixel-lab-sandbox/images` 与 `output`。
2. 用绝对路径和相对路径分别定位同一文件。
3. 运行一个打印 `Path.cwd()` 与 `sys.executable` 的 Python 脚本。
4. 用 `ps -ef` 找到当前 shell 或 Python 进程，并说明哪一列是进程 ID。
5. 把一个文件名大小写改错，记录失败和修正。不要在本练习中使用 `sudo` 或递归删除。

### 没有 Linux/WSL 环境

1. 为上述五步写出 Linux 与 PowerShell 双栏命令。
2. 画出 `/home/student/pixel-lab` 的目录树，并从三个不同起点推导 `images/input.pgm`。
3. 阅读一段 Linux README，圈出平台相关命令、通用概念和需要实机确认的假设。
4. 保留“未来实机复测”清单，不把推演写成已运行结果。

## 11. 实际使用

为 Pixel Lab README 增加简短的平台对照：Windows 使用 `.venv\Scripts\python.exe`，Linux 使用 `.venv/bin/python`；输入、输出与验收不变。Linux 不是 Pixel Lab Stage 0 出口的硬件或操作系统要求，Windows 上完整证据同样有效。

## 12. Mastery Evidence 掌握证据

路线只要求 `understood`：一份正确的命令对照、路径推演和平台边界说明即可支持理解判断。若要达到 `mastered`，还需在真实 Linux/WSL 环境提交 `pwd`、`ls`、解释器、脚本与进程输出，并解释每项证据；推演不能冒充实机结果。
