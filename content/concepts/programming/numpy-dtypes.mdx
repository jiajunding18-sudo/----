# NumPy dtype、数值范围与 copy/view（NumPy Dtypes, Numeric Ranges, and Copy/View）

本页只处理机器视觉中最常见的两个数据契约：数值以什么类型保存，以及一个新变量是否仍与原数组共享数据。目标不是记住全部 NumPy dtype。

## 1. 这是什么

**数据类型（data type, `dtype`）**规定数组中每个元素如何存储和解释。常见图像会使用 `uint8`：无符号 8 位整数，只能表示 0 到 255。算法计算也常使用 `float32` 或更宽的有符号整数。

```python
import numpy as np

image = np.array([0, 127, 255], dtype=np.uint8)
print(image.dtype)  # uint8
```

另一个容易混淆的概念是 **view 与 copy**：view 与原数组共享底层数据；copy 拥有独立数据。两者可能有相同的 shape 和 dtype，却有不同的修改行为。

## 2. 为什么机器视觉需要它

### 为什么现在学

你已经能切片和批量运算数组。现在必须知道这些运算是否越过 dtype 范围，以及切出的 ROI 是否会把修改传回原图，否则后续显示、阈值、滤波和保存结果都可能悄悄错误。

### 在机器视觉中会在哪里使用

- 增亮、相减、归一化和滤波前选择安全计算类型；
- 解释 `uint8` 图像的 0–255 与浮点图像的数值约定；
- 防止中间结果 overflow（溢出）或 underflow（下溢/回绕）；
- 决定 ROI 修改应作用于原图，还是应在独立副本中进行；
- 检查算法输入、计算中间量与输出保存之间的转换边界。

## 3. 前置知识

硬前置是 `python.numpy-arrays`：应能读取 `shape`、`ndim`、`dtype`，并用 slicing 得到 ROI。Stage 1 的 `math.numerical-stability` 提供“数值表示会影响可靠性”的背景，但它不是本页 hard dependency；本页聚焦可直接观察的 dtype 行为。

## 4. 核心概念

### dtype 与数值范围

| dtype | 当前需要知道的范围/特点 | 常见用途 |
| --- | --- | --- |
| `uint8` | 整数 0–255，不能表示负数 | 常见 8-bit 图像存储 |
| `int16` | 可表示负数，范围比 `uint8` 宽 | 小型加减运算的安全中间类型 |
| `float32` | 可表示小数和负数 | 归一化、滤波和模型计算 |

dtype 与“图像看起来是什么”不是同一件事。`float32` 数组可能约定在 0–1，也可能仍是 0–255；必须同时记录 dtype、实际 `min/max` 和数据约定。

### overflow、underflow 与安全转换

当结果超出固定整数 dtype 可表示的范围时，底层整数运算可能回绕。例如 `uint8` 的 250 加 20，若运算仍在 `uint8` 中进行，就不能得到 270。

稳妥的基本流程是：

1. 转到能容纳中间结果的 dtype；
2. 完成运算；
3. 按目标范围裁剪（clip）；
4. 明确转回目标 dtype。

```python
safe = np.clip(image.astype(np.int16) + 20, 0, 255).astype(np.uint8)
```

`astype` 通常会产生转换后的新数组。不要把“最终要保存为 `uint8`”误解为“所有中间计算都必须使用 `uint8`”。

### 隐式转换不能替代检查

不同 dtype 混合运算时，NumPy 会按照类型规则决定结果 dtype。当前不要求背完整规则；工程上应在关键边界打印或断言结果 dtype，而不是猜测。

```python
normalized = image.astype(np.float32) / 255.0
assert normalized.dtype == np.float32
assert 0.0 <= normalized.min() <= normalized.max() <= 1.0
```

### view 与 copy

基本 slicing 通常返回 view。修改 view，原数组相同位置也会改变：

```python
roi_view = image2d[0:2, 0:2]
roi_copy = image2d[0:2, 0:2].copy()
```

- 想原地修改原图的一块区域，可以有意使用 view；
- 想保留原图并独立实验，应显式 `.copy()`；
- 不确定时，可用 `np.shares_memory(a, b)` 检查是否共享内存。

当前只需理解可观察的共享修改行为，不学习 stride、底层内存布局或完整高级索引规则。

## 5. 初学者直觉解释

dtype 像一个有边界的量杯：`uint8` 只能装 0–255。把计算塞进过小的量杯，程序可能继续运行，但数字已经不是你想表达的物理或亮度含义。

view 像同一张纸上的窗口，copy 像复印件。改窗口里看到的内容会改原纸；改复印件不会。

## 6. 必须掌握到什么程度

- 能在运算前后检查 dtype、数值范围和单位/约定。
- 能独立处理 `uint8` 加减中的 overflow / underflow。
- 能使用 `astype`、`clip` 和断言建立安全转换边界。
- 能预测并验证切片修改是否传播，按意图选择 view 或 copy。

当前不学习全部 dtype 转换规则、位级表示、stride、缓存优化、structured dtype 或性能调优。

## 7. 常见误区

- 代码未报错，就认为数值一定正确。
- 只看 dtype，不看实际 min/max 和 0–1、0–255 等数值约定。
- 直接在 `uint8` 中做可能产生负数或超过 255 的运算。
- 以为所有切片都会复制数据，修改 ROI 后意外改变原图。
- 为避免共享一律复制所有数组，既不说明意图也增加不必要的内存占用。

## 8. Worked Example：安全亮度运算与共享修改

```python
import numpy as np

bright = np.array([250], dtype=np.uint8)
dark = np.array([5], dtype=np.uint8)

# 明确让两侧都保持 uint8，复现回绕现象。
wrong_bright = bright + np.array([20], dtype=np.uint8)
wrong_dark = dark - np.array([10], dtype=np.uint8)
print(wrong_bright[0], wrong_dark[0])  # 14, 251

safe_bright = np.clip(bright.astype(np.int16) + 20, 0, 255).astype(np.uint8)
safe_dark = np.clip(dark.astype(np.int16) - 10, 0, 255).astype(np.uint8)
assert safe_bright[0] == 255
assert safe_dark[0] == 0

source = np.arange(9, dtype=np.uint8).reshape(3, 3)
roi_view = source[0:2, 0:2]
roi_copy = source[0:2, 0:2].copy()

assert np.shares_memory(source, roi_view)
assert not np.shares_memory(source, roi_copy)

roi_view[0, 0] = 255
assert source[0, 0] == 255

roi_copy[0, 1] = 200
assert source[0, 1] != 200
```

第一个对照说明：错误结果仍可能是合法 `uint8`，所以“没有异常”不是正确性证据。第二个对照中，view 与 copy 的 shape、dtype 相同；只有共享关系不同。完成图像操作时应把这种关系写成明确选择。

## 10. Practice 练习

### 理解检查

判断下面说法并解释：`dtype=float32` 的图像一定在 0–1。完成标准：回答“错误”，并指出还需检查实际 min/max 和数据约定。

### 数值练习

对 `[0, 5, 250, 255]` 的 `uint8` 数组分别加 20、减 10；先复现回绕，再使用 `int16 → clip → uint8` 修复。完成标准：输出均在 0–255，边界期望分别可由断言验证，并记录每一步 dtype。

### 视觉小练习

创建一个 `4×5` 灰度数组，取中心 ROI。分别通过 view 和 copy 将 ROI 置零。完成标准：运行前先预测原图是否改变；使用 `np.shares_memory` 与数组对照验证预测；说明实际图像处理中为何选择其中一种。

### 错误诊断

给一段“直接对 `uint8` 图像做减法”的代码，找出一个不会抛异常但会产生错误亮度的输入。完成标准：保存错误值、安全值、两者 dtype，并解释错误来自表示范围而非 NumPy 随机故障。
