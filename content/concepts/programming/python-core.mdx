# Python 核心语法（Python Core Syntax）

本单元只学习足够表达小型实验的数据与流程。目标是**先预测，再运行，再解释差异**。

## 1. 这是什么

Python 源码由表达式和语句组成。变量给对象起名字；类型决定值能参与哪些操作；列表（list）保存有顺序的一组值；字典（dict）用键查值；`if` 选择分支；`for` 重复处理；函数（function）把输入变成明确的返回值。

## 2. 为什么机器视觉需要它

图像以后会表现为数组，但实验仍要保存文件名、曝光时间、类别与测量值，遍历样本，检查条件并汇总结果。若不理解基本控制流，调用再高级的视觉库也无法判断结果是否可信。

## 3. 前置知识

没有硬前置。推荐先学习“计算机、文件与终端”，以便清楚源码文件与运行中对象的区别。

## 4. 核心概念

- `int`、`float`、`str`、`bool` 分别表达整数、近似实数、文本和真假。
- 赋值 `name = value` 让名字引用一个对象，不是数学等式。
- 列表适合按顺序遍历；字典适合描述一条记录的命名字段。
- `if / elif / else` 只执行首个为真的分支。
- `for item in items` 逐个绑定元素；循环体用缩进表示边界。
- 函数的参数是输入，`return` 是输出；打印只是观察，不等于返回。

## 5. 初学者直觉解释

把一条图像记录想成贴有标签的样品袋：字典的键是标签，列表是一排样品袋。循环把袋子逐个放到工作台，条件决定放入哪个篮子，函数则是一套可以重复执行且输入输出明确的操作规程。

## 6. 必须掌握到什么程度

你应能不看范例写出十几到几十行脚本：创建数据、封装函数、遍历记录、进行条件判断并返回汇总；还能用纸笔追踪一次循环。暂时不要求类、装饰器、生成器或复杂算法技巧。

## 7. 常见误区

- 用 `=` 比较两个值；比较相等应使用 `==`。
- 把 `print(result)` 当成函数已经 `return result`。
- 修改代码直到“没有报错”，却不先写预期结果。
- 对浮点数要求任意计算都精确相等；多数测量需要合理容差。
- 用一个含义不清的列表同时保存文件名、亮度和标签。

## 8. Worked Example：汇总曝光记录

先手算：下面三条记录有两条亮度低于 80，平均亮度是 80。

```python
records = [
    {"name": "desk.jpg", "brightness": 62},
    {"name": "window.jpg", "brightness": 135},
    {"name": "book.jpg", "brightness": 43},
]


def summarize(items, dark_threshold):
    total = 0
    dark_names = []

    for item in items:
        brightness = item["brightness"]
        total = total + brightness
        if brightness < dark_threshold:
            dark_names.append(item["name"])

    average = total / len(items)
    return {"average": average, "dark_names": dark_names}


result = summarize(records, dark_threshold=80)
print(result)
```

追踪第一轮：`item` 指向 `desk.jpg`，`total` 从 0 变为 62，条件为真，`dark_names` 变为 `['desk.jpg']`。若实际输出与手算不同，先找第一处不一致，而不是猜最终答案。

## 9. Active Recall 主动回忆

1. 列表和字典分别解决什么问题？
2. `print` 和 `return` 有何不同？
3. 循环一次后，哪些变量改变了？
4. 把阈值从 80 改成 43，哪几条记录进入 `dark_names`？为什么？
5. 空列表会让示例在哪一步失败？

## 10. Practice 练习

1. 为每条记录加入 `exposure_ms`，写函数返回曝光时间最长的文件名。
2. 为 `summarize` 增加空列表处理：先写期望行为，再选择返回值或错误提示。
3. 换成四条自造记录，手算平均值与分类，再运行对照。
4. 画一张包含每轮 `item`、`total`、条件结果和 `dark_names` 的追踪表。

## 11. 实际使用

把手机拍摄的三张照片名称和你人工给出的“偏暗/正常”观察写成记录。此处不计算真实像素亮度；重点是先把实验对象和判断规则表达清楚，避免把人工标签伪装成算法测量。

## 12. Mastery Evidence 掌握证据

证据应包含：未经逐行复制独立写出的汇总函数；至少两组输入的手算预期；运行输出；一次边界输入；一张循环追踪表；以及对 `return`、分支顺序和数据结构选择的解释。只展示“代码能跑”不足以证明掌握。

## 13. 后续复用与复习

NumPy 数组处理、OpenCV 批量读图、数据集划分和模型评估都会复用这些结构。次日从空文件重写示例；7 天后把记录字段换掉但保留处理结构，确认你掌握的是模式而非答案。
